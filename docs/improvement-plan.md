## 2. 功能改进清单

优先级：**P0 = 不做就不满足提交要求或主题**；P1 = 显著加分；P2 = 时间允许再做。

### P0-1 出海 Agent 编排层（核心）

**设计**：规划-执行（Plan-and-Execute）式 Agent，不依赖各家原生 function calling，复用现有 `services/translate.py::build_ai_request_args`，四种协议（Gemini / OpenAI / OpenAI-Response / Anthropic）都可用。

```
用户一句话需求
   │
   ▼
① 意图解析（LLM → JSON）：目标市场[]、平台、受众、语气、时长策略、是否保留原声
   │
   ▼
② 生成计划卡片（LLM → JSON 步骤列表，附每步理由）──► 用户「确认 / 修改」
   │
   ▼
③ 执行：每个市场一个子任务，调用现有流水线工具
   语音识别 → 本地化翻译 → [④ 市场审查] → 选音色 → 配音合成 → 成片
   │
   ▼
④ 市场审查（LLM）：禁忌/敏感表达、夸大宣传、单位货币、称谓、宗教文化
   输出问题清单（字幕序号、原因、修改建议）──► 用户「全部采纳 / 逐条处理」
   │
   ▼
⑤ 平台文案（LLM）：当地语言标题 ×3、描述、话题标签
   │
   ▼
⑥ 交付「出海素材包」+ 自检报告；用户可继续用自然语言提修改 → 局部重做
```

**后端改动**

- [ ] 新增 `server/services/agent.py`
  - `parse_intent(prompt) -> Intent`、`make_plan(intent) -> list[Step]`、`review_market(segments, market) -> list[Issue]`、`gen_platform_copy(segments, market, platform) -> Copy`、`revise(segments, instruction) -> list[Edit]`
  - 全部用 JSON 输出 + 校验 + 失败重试一次，复用 `_extract_json_array` 思路
  - 市场配置表 `MARKETS`：`jp / sea-th / sea-id / us / mena / eu-de …` → 语言、默认音色、单位、货币、审查要点、主流平台
- [ ] 新增 `server/routers/agent.py`
  - `POST /api/agent/session`：创建出海项目（campaign），入参 `source_task_id` + `prompt`，返回意图与计划
  - `POST /api/agent/session/{id}/confirm`：确认计划，按市场创建子任务并启动
  - `GET  /api/agent/session/{id}`：会话状态、每个市场的步骤进度、Agent 思考日志
  - `POST /api/agent/session/{id}/review/{market}`：提交审查处理结果（采纳/忽略/手改）
  - `POST /api/agent/session/{id}/message`：自然语言修改（"第 3 句太生硬""日本版换成女声"）
  - 会话存 `workspace/campaigns/{id}/session.json`，原子写
- [ ] **流水线插入"人工审查"暂停点**：`TaskStartRequest` 增加 `pause_after: Literal["translate"] | None`；`_execute_pipeline` 翻译完成后若设置该字段则置新阶段 `TaskStage.AWAITING_REVIEW` 并返回；确认后再次 `start`，前 3 步全部命中缓存继续执行
- [ ] **每个市场单独一个任务**（必须）：现有 `chunk_XXX.mp4` / `final.mp4` 文件名不含语言，同一任务换目标语言会复用旧语言分片（`server/routers/task.py:611`、`:619`）。子任务通过硬链接/复制源视频与 `audio.aac`、`subtitles_src.json` 创建，ASR 只跑一次
- [ ] 注册路由（`server/main.py`），沿用 `guard_api_origin`

**验收**：输入示例提示词，60 秒内返回计划；确认后两个市场并行处理；翻译后停在审查；采纳建议后继续生成成片。

### P0-2 字幕修改 + 局部重配音（Agent "改稿"能力的底座）

- [ ] `PUT /api/task/{id}/subtitles`：按 index 修改 `translated_text`，原子写回 `subtitles_{lang}.json`
- [ ] 重渲染时只删除受影响的 `chunk_XXX.mp4`、`dub_XXX.wav` 与 `final.mp4`；未改动句子命中 TTS 内容哈希缓存（`tts.py::_tts_cache_path`）
- [ ] 注意 `_build_tts_utterances` 会合并相邻短句 → 以合并后的配音句判断受影响分片
- [ ] 前端字幕列表行内编辑 + "N 处修改未生效 · 重新生成"

### P0-3 公网部署与评审访问

当前安全模型只信任 `localhost` 来源，且密钥由浏览器提交，评委没有密钥，**不改无法公网演示**。

- [ ] 新增"托管模式"环境变量 `SHIYIBAO_HOSTED=1`：
  - `SHIYIBAO_ALLOWED_HOSTS=demo.xxx.com` 加入来源白名单（`server/security.py`）
  - 简易登录：`SHIYIBAO_DEMO_USER / SHIYIBAO_DEMO_PASS` → 签发 HttpOnly Cookie；未登录拒绝 `/api/*`
  - 服务端注入密钥：`start_task` 与 Agent 在请求未带 Key 时使用环境变量密钥（现 `start_task` 会因空 Key 返回 400）
  - 隐藏/禁用 `/api/settings` 返回密钥、`register-local`、`scan-directory`、`open_folder` 等本机文件能力
  - 限流：每账号同时 1 个任务、上传 ≤ 200MB、视频 ≤ 3 分钟，防止评审期间费用失控
- [ ] Docker 部署到云服务器（2C4G 起，国内访问稳定的区域），HTTPS（Caddy 自动证书）
- [ ] 预置 2–3 个已完成的示例项目，评委无需等待也能看到完整结果
- [ ] 必剪 ASR、Gemini/MiMo 从服务器出网连通性实测

## 3. UI 改版方案

**设计原则**：从"翻译工具"变成"出海助理"；评委 3 秒看懂"这是一个会规划、会干活、会听意见的 Agent"。

**视觉**：主色海蓝 `#0B4F8A`、点缀中国红 `#C8102E`、浅色底；元素：航线、地球/地图、国旗；去掉原 SaaS 紫色与"华章"宣纸墨绿（若 D2 选文化出海则保留墨绿+朱砂）。

| 页面 | 现状 | 改版 |
|---|---|---|
| **首页 `/`** | 大上传区 + 日志 | 左：一句话需求输入框 + 上传/链接；下方 3 张**示例提示词卡片**（即提交要求的 3 个提示词）。右：目标市场地图，可点选多个国旗 |
| **计划确认（新）** | 无 | Agent 解析出的需求摘要 + 步骤卡片（每步一句理由），按钮「确认执行」「我要修改」 |
| **执行页 `/task/:id`** | 进度条 + 日志流 | 按市场分栏的**步骤时间线**：⏳/✅/⚠️ 状态、每步 Agent 思考摘要、耗时；审查节点弹出问题清单（原文/译文/问题/建议，可逐条采纳） |
| **结果页** | 双卡片播放器 + 字幕 + AI 学习 | 顶部市场切换 Tab；左：原片/译配版对比播放；右：字幕可编辑、平台文案卡片（一键复制）、审查报告；底部：效果度量卡片 + 「下载出海素材包」；右下角 Agent 对话框（自然语言改稿） |
| **项目档案 `/history`** | 任务列表 | 以"出海项目"为单位，显示覆盖市场数、状态、缩略图 |
| 音色库 / 性能调度 | — | 保留，导航后移；托管模式隐藏性能调度 |

**前端改动文件**：新增 `components/AgentHome.tsx`、`PlanConfirm.tsx`、`AgentTimeline.tsx`、`ReviewPanel.tsx`、`CampaignResult.tsx`、`lib/agent-api.ts`、`lib/markets.ts`；修改 `App.tsx` 路由、`Navbar.tsx` 品牌、`HistoryView.tsx`；`ResultState.tsx` 中的播放器与字幕组件拆出复用。

## 5. 提交材料

### 三个示例提示词（必须在链接中可实际运行）

1. **电商**："把这条保温杯带货视频做成 TikTok 日本站版本，面向 25–35 岁上班族女性，语气亲切，标出不符合日本广告法的说法。"
2. **多市场**："同一条产品介绍视频，同时出泰国和印尼版本，给每个版本配 3 个当地语言标题和话题标签。"
3. **文化出海**："把这段非遗剪纸讲解视频翻成英文，面向欧美年轻人，保留专有名词并在字幕里解释文化含义。"

### PPT 大纲（≤20 页，16:9，≤50MB，匿名）

1 封面 / 2 出海视频本地化痛点（成本、周期、文化踩坑）/ 3 目标用户与场景 / 4 现有方案对比 / 5 产品一句话 + 核心流程 / 6 Agent 架构图 / 7 意图解析与规划 / 8 市场审查机制 / 9 人机协同改稿 / 10 技术栈与开源基座说明（**区分团队新增**）/ 11–13 三个案例实测（输入、过程截图、输出）/ 14 效果数据 / 15 部署与安全 / 16 商业模式与落地路径 / 17 局限与风险 / 18 后续规划 / 19 团队分工（脱敏）/ 20 致谢

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 8 天工期不够 | 11/6 功能冻结；P1 可砍，P0 不可砍；审查与文案都是纯 prompt，最省工 |
| 外部接口（必剪 ASR、Gemini、MiMo）评审期间不稳定或欠费 | 预置已完成示例；Key 余额监控；准备备用模型；演示视频提前录 |
| LLM 输出 JSON 不稳 | 严格 schema 校验 + 重试 + 降级为默认计划 |
| 公网暴露密钥/被滥用 | 托管模式登录 + 限流 + 关闭本机文件接口；密钥只在服务端 |
| MiMo 不支持某些语种配音 | 实测后在市场配置中标"仅字幕" |
| 被质疑"只是套壳开源项目" | PPT 第 10 页明确开源基座与团队新增（Agent 层、市场审查、托管模式、UI），保留 git 提交记录 |
| 许可与素材侵权 | 补 LICENSE 依据；演示视频自拍或取得书面授权；音乐用无版权素材 |
| 并行修改冲突 | 先停另一边改动或按目录分工，每天合并一次 |
